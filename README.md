# Hybrid QNN for Quantitative XRD-CT

Reproducible battery XRD-CT workflow for a six-qubit hybrid quantum-classical neural network. The repository covers synthetic mixture generation, noise-injected pre-training, IBM Quantum deployment, hardware-domain head recalibration, and quantitative experimental inference.

## Workflow

### 1. Generate mixtures and pre-train

The library stores one simulated diffraction-pattern pool per phase. A training sample is generated by first choosing the number of phases with probabilities

`P(single, dual, triple, four) = (0.03, 0.62, 0.30, 0.05)`.

The selected phase coefficients are then sampled in the **scale-coefficient domain**, using an anchor/strong/ghost rule. Targets are never sampled uniformly in the weight-fraction domain. For phase `i`,

```text
effective_sf_i = coefficient_i * fixed_sf_i
relative_weight_i = effective_sf_i * unit_cell_volume_i * unit_cell_mass_i
weight_fraction_i = relative_weight_i / sum(relative_weight)
```

The fixed scale factors are `7e-10`, `8e-9`, `1e-9`, and `4e-10` in the phase order LCO, Graphite, Al, and Cu. Rows with invalid patterns or lattice metadata are excluded from sampling. The mixed pattern is max-pooled to 64 values and L2-normalized before amplitude encoding. The unnormalized pattern maximum is retained only for the scale-factor head.

```powershell
python scripts/01_generate_battery_dataset.py `
  --library D:/data/pintype_diffraction_library.h5 `
  --output data/battery_200k.h5

python scripts/01_pretrain_battery_dual_head.py `
  --dataset data/battery_200k.h5 `
  --output outputs/pretraining
```

Pre-training uses stochastic Pauli gate-error injection (`p1q=5e-4`, `p2q=5e-3`) and finite-shot sampling at 2048 effective shots. The QNN and both heads are optimized jointly, after which the QNN is frozen and the existing head weights continue training independently.

### 2. Execute the frozen QNN on IBM hardware

The QNN uses six-qubit amplitude encoding, two `Rx-Ry-Rz` plus ring-entanglement repetitions, and the `X`, `Y`, and `Z` single-qubit observables. Its 36 trainable circuit parameters produce 18 quantum features.

Prepare the 20,000 simulated calibration patterns and the experimental mask pixels:

```powershell
python scripts/02_prepare_qpu_inputs.py --kind simulated `
  --input data/battery_200k.h5 --output data/qpu_simulated_20k.npz --count 20000

python scripts/02_prepare_qpu_inputs.py --kind experimental `
  --input D:/data/battery_xrdct.h5 --patterns-key patterns --mask-key Mask `
  --output data/qpu_experimental.npz
```

IBM credentials are read only from the environment:

```powershell
$env:QISKIT_IBM_TOKEN = "..."
$env:QISKIT_IBM_INSTANCE = "crn:v1:..."
```

Compile locally onto 18 disjoint six-qubit paths, submit through one Runtime Batch, and download the features:

```powershell
python scripts/02_qpu_batch.py compile --inputs data/qpu_simulated_20k.npz `
  --checkpoint outputs/pretraining/battery_dual_head.pt --output outputs/qpu_simulated
python scripts/02_qpu_batch.py submit --inputs data/qpu_simulated_20k.npz `
  --checkpoint outputs/pretraining/battery_dual_head.pt --output outputs/qpu_simulated
python scripts/02_qpu_batch.py download --inputs data/qpu_simulated_20k.npz `
  --checkpoint outputs/pretraining/battery_dual_head.pt --output outputs/qpu_simulated
```

Repeat these commands for `qpu_experimental.npz`. Each pattern is measured in Z, X, and Y, so it contributes three PUBs. Eighteen replicas reduce variance. The requested 2048 effective shots require 114 physical shots per replica, producing 2052 actual effective samples; the exact values are recorded in every receipt.

### 3. Freeze the QNN and recalibrate both heads

Hardware features from the simulated calibration set are split 80/10/10. PMN statistics are fitted once on the hardware training features and then fixed. The weight-fraction and scale-factor heads are optimized separately, preventing one target from dominating the other.

```powershell
python scripts/03_retrain_hardware_heads.py `
  --inputs data/qpu_simulated_20k.npz `
  --features outputs/qpu_simulated/features `
  --checkpoint outputs/pretraining/battery_dual_head.pt `
  --output outputs/retrained_heads
```

### 4. Apply the recalibrated heads to experimental XRD-CT

```powershell
python scripts/04_deploy_experimental.py `
  --inputs data/qpu_experimental.npz `
  --features outputs/qpu_experimental/features `
  --checkpoint outputs/retrained_heads/hardware_retrained_dual_head.pt `
  --output outputs/experimental_predictions.npz
```

The output contains weight-fraction and effective-scale-factor maps in the original XRD-CT image geometry. Pixels outside the supplied mask remain zero.

## Architecture

- **Quantum feature extractor:** 64 amplitudes, 6 qubits, 2 repetitions, 36 trainable parameters, ring entanglement, and 18 `X/Y/Z` expectation features.
- **Weight head:** `18 -> 64 -> 64`, four independent `64 -> 64 -> 64 -> 32 -> 1` branches, followed by softmax so the four fractions sum to one.
- **Scale-factor head:** the 18 quantum features plus the raw pattern maximum, `19 -> 64 -> 64`, four independent branches, and linear outputs.
- **Domain alignment:** fixed PMN statistics estimated from hardware calibration features and reused unchanged for experimental inference.

## Reproducibility Notes

- Large HDF5, QPY, NPZ, checkpoint, and credential files are intentionally excluded from Git.
- Every hardware group writes a receipt containing its job ID, pattern range, PUB count, physical shots, and actual effective shots.
- Do not commit IBM API tokens, CRNs, local credential files, or absolute machine-specific paths.
- The default configuration reproduces the paper pipeline; sampling, noise, backend, and worker counts remain explicit in `configs/battery.yaml`.
